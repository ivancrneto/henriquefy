**Rule.** Aim at effectiveness, doing the right thing for the moment, not efficiency, doing a lot
quickly. Effectiveness accepts imperfection, errors and missing information: do what can be done
now and trust a later iteration to fix the rest. It is not getting it right the first time; it is
correcting course fast enough that the project survives. In software that means delivering a
small piece of value every day instead of building the ideal model and the scalable setup first.

**Why Henrique says so.** He contrasts the two mentalities the course has been about: efficiency
seeks to do much, very fast; effectiveness seeks the right thing for that moment (lesson 1,
0:06:51 to 0:07:06, `verified: false`, transcript paraphrase), and it is what lets you accept
imperfection and trust a future iteration (0:08:38 to 0:08:57). On a student's plan to test
options A and B with a client for a week each, he agrees: the problem is not testing two things,
it is doing what you do not know without seeing how to avoid waste; the focus on effectiveness is
not getting it right first, it is correcting course fast so it does not sink the project (lesson
4, 0:11:28 to 0:12:19). And for code: let go of the ideal, the great data model and the scalable
environment, deliver a tiny value each day, because code that is not running does nothing
(lesson 3, 0:10:09 to 0:10:37). Digest sections 6.2 and 6.6.

**Looks like.** Two candidate solutions tried for a week each with agreed indicators, and the
worse one dropped. Bad: weeks spent on a perfect schema and infrastructure before anyone uses the
feature. See `funcione-direito-e-depois-rapido` and `nao-projete-a-generalizacao`, which carry
the code side.

**How to detect.** No code signal of its own; in code it shows up through
`nao-projete-a-generalizacao` and `funcione-direito-e-depois-rapido`. `ask` mode: questions about
priorities, perfectionism, or how to start a project.

**How to fix.** Name the right thing for this week. Cut scope until it can run and be used now.
Decide how you will know it was wrong and how you will correct it.
